# ai-pm

**Персональный продуктовый агент, который помнит, зачем вы развиваете продукт,
следит за работой исполнителей и сам возвращается с результатом или важным
вопросом.**

Он нужен владельцу одного или нескольких продуктов, которому надоело каждый раз
заново объяснять контекст, проверять очередь задач и спрашивать: «ну что там?».
Вы формулируете потребность обычными словами, а ai-pm ведёт её до наблюдаемого
результата: выбирает ближайший полезный шаг, передаёт техническую работу агентам,
следит за ходом и сообщает только то, что действительно требует внимания.

> **Например:** вы пишете «пользователи не понимают продукт по README».
> ai-pm сохраняет эту потребность, описывает проверяемый сценарий, отдаёт правку
> исполнителю, следит за ревью и публикацией, а затем проверяет результат как
> пользователь — открывает опубликованную страницу. Вам приходит не журнал
> внутренних действий, а итог или конкретный вопрос, без которого дальше нельзя.

## Что меняется для вас

Без ai-pm продуктовая работа часто живёт между чатами, задачами и памятью
человека. Агент собирает этот разрыв в один непрерывный путь:

1. **Вы называете боль или желаемый результат.** Не нужно заранее превращать
   запрос в техническое задание.
2. **ai-pm удерживает продуктовый контекст.** Он знает текущую ставку, принятые
   решения, границы продукта и то, что решено не делать.
3. **Исполнители делают техническую работу.** ai-pm передаёт задачу в
   [task-agent](https://github.com/rdudov/task-agent), наблюдает прогон и не
   подменяет собой разработчика.
4. **Результат проверяется по пользовательскому сценарию.** Коммит и зелёные
   тесты сами по себе не считаются доставленной пользой.
5. **Вы видите состояние и получаете сигнал.** Доска показывает, что идёт, что
   стоит и почему; письмо или push приходят, когда нужен ваш выбор или появился
   значимый результат.

Так выглядит полный цикл:

```text
ваша потребность
      ↓
контекст и ближайший полезный шаг
      ↓
задача → исполнитель → независимое ревью
      ↓
живая проверка результата
      ↓
итог вам или один конкретный вопрос
```

## Чем ai-pm отличается от обычного агента задач

| | Обычный агент задач | ai-pm |
|---|---|---|
| Главный вопрос | «Как выполнить эту задачу?» | «Какой результат сейчас важнее для продукта?» |
| Память | Контекст текущего запуска | Долговечные снимки продуктов, решения и план |
| После запуска | Возвращает ответ или код | Наблюдает работу до проверки и доставки результата |
| Мера готовности | Задача технически завершена | Пользовательский сценарий действительно работает |
| Общение | Показывает ход выполнения | Отделяет внутренний шум от того, что требует вашего внимания |

`task-agent` и ai-pm не конкурируют. Первый организует исполнение и ревью
конкретных задач; второй решает, какую продуктовую работу запускать, наблюдает её
эффект и разговаривает с человеком.

## Попробовать за несколько минут

Нужны Linux, Python 3.12 и уже установленный рядом
[task-agent](https://github.com/rdudov/task-agent). Модель и почта для первого
знакомства не нужны: сначала можно создать продукт и открыть доску на локальных
данных. Если путь к `task-agent` неверен или его контракт несовместим, команды
наблюдения откажут с объяснением, а не покажут пустую доску.

```bash
git clone https://github.com/rdudov/ai-pm.git
cd ai-pm

# Опишите свою установку.
cp threads.example.json threads.json
$EDITOR threads.json

# Создайте долговечный снимок первого продукта.
python3 scripts/product_memory.py --init --start-product demo
$EDITOR content/products/demo/snapshot.md
python3 scripts/product_memory.py --check

# Посмотрите состояние направления и соберите автономную HTML-доску.
python3 scripts/thread_state.py product --format text
python3 scripts/process_map_serve.py --out board.html
```

В `threads.json` для этого примера достаточно заменить:

- `tasks_repo` — путь к установленному `task-agent`;
- `mail_to` — можно оставить пустым;
- у направления `product`: `products` на `["demo"]`, а `repos` — на пути
  репозиториев вашего продукта.

Откройте `board.html` в браузере. На ней должны быть направления, их текущее
состояние, ближайшая работа и отдельная строка о том, требуется ли что-то от
вас. Для живого режима с автообновлением:

```bash
python3 scripts/process_map_serve.py --serve 8765
# затем откройте http://127.0.0.1:8765
```

Подвал живой страницы показывает установленную ревизию. Если сохранить страницу
в файл, подвал прямо назовёт её снимком и оставит ссылку обратно на адрес живой
доски. Для снимка, собранного командой, адрес можно указать явно:
`--live-page-url http://127.0.0.1:8765/`.

Это уже полезный локальный результат. Чтобы ai-pm самостоятельно просыпался,
ставил работу и писал вам, подключите Claude Code или Codex CLI,
почтовый или push-канал при необходимости и systemd-таймеры из `systemd/`.
Перед первым реальным запуском прочитайте [AGENTS.md](AGENTS.md) — там лежит
каноническая продуктовая логика агента, а не инструкция по программированию.

## Что хранится где

- **В git:** переносимое ядро — правила, наблюдение, доска, таймеры и почтовая
  дверь.
- **Вне git:** содержимое вашей установки — снимки продуктов, история решений,
  портфельный план, настройки направлений и рабочее состояние.
- **В task-agent:** задачи, технические исполнители, проверки и их артефакты.

Так личный контекст не попадает в публичный репозиторий, а ядро можно обновлять
и переносить между установками.

## Границы продукта

ai-pm — не универсальный таск-трекер, не автономная «компания из агентов» и не
замена владельцу продукта. Он не придумывает ваши цели и не принимает за вас
решения с реальной ценой или риском. Его работа — сохранять контекст, вести
согласованный приоритет до результата и вовремя вернуть вам выбор, который
нельзя честно сделать автоматически.

Из коробки это инструмент для личной Linux-установки, где рядом есть
`task-agent` и один из поддерживаемых агентских CLI. Фоновый режим опирается на
systemd; внешние каналы связи настраиваются отдельно. Без них остаются рабочими
локальные снимки, наблюдение и статическая доска.

## Разработка и проверка

Почти всё работает на стандартной библиотеке Python. Полный набор тестов требует
`pytest`:

```bash
python3 -m venv .venv
.venv/bin/pip install pytest
cd scripts && ../.venv/bin/python -m pytest
```

Перед публикацией настройте обязательную проверку утечек и публичную личность
коммитов:

```bash
git config core.hooksPath hooks
mkdir -p state
$EDITOR state/private-history-markers
git config user.name "ai-pm"
git config user.email "ai-pm@users.noreply.github.com"
```

Файл `state/private-history-markers` содержит по одному приватному имени в
строке и не попадает в git. Pre-push hook проверяет исходящие изменения,
метаданные коммитов, приватные пути и секреты через установленный `task-agent`;
если проверка недоступна или устарела, список маркеров пуст либо в checkout
настроено больше одного remote, публикация останавливается.
