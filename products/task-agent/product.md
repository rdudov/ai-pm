# Task Agent

## Концепция
Долговременная память и дисциплина исполнения для работы с агентом: каждый
нетривиальный запрос становится папкой задачи с планом, проверкой и следом.
Заменяет разговор, который исчезает вместе с контекстом окна. Приватный контур —
`/opt/projects/companion-agent`, публичный форкаемый скелет — `/opt/projects/task-agent`.

## Текущая ставка
Свидетельство, привязанное к наблюдению, а не к прозе исполнителя: гейт без
фактической команды и наблюдённого значения не должен считаться пройденным
(задача 706, находки AR-001..AR-004).

## Не делаем
- Новый оркестратор, DSL выражений или plugin-слой поверх существующих владельцев.
- Расширение контракта декларативными полями, которые заполняет тот же исполнитель.

## Куда он развивался
По истории задач: от создания артефактов задач к делегированию детям, затем к
унификации `/codex` и `/task` на одном профилированном жизненном цикле (проект
`unified-task-execution`, задачи 676–683) и к разбору долга по незакрытым
задачам (`task-debt-cleanup`). То есть направление — не новые возможности, а
надёжность исполнения и восстановление после сбоя.
